# Архитектура проекта «Аналитика розничных продаж»

Учебная информационно-аналитическая система (ИАС), построенная по классической
трёхслойной схеме хранилища данных: **источник → ETL → хранилище (DWH) → аналитика/BI**.

## 1. Назначение

Демонстрация полного цикла работы ИАС на данных розничных онлайн-продаж:

- проектирование и создание реляционной БД (СУБД MariaDB/MySQL);
- ETL-процесс: извлечение, очистка, преобразование, загрузка;
- многомерная модель данных «звезда» (star schema);
- аналитический слой: витрины-представления и SQL-запросы;
- расчёт KPI и продвинутая аналитика на Python (тренды, сезонность, ABC-анализ,
  RFM-сегментация клиентов, когортный анализ удержания);
- визуализация: статический HTML-отчёт + интерактивный дашборд.

## 2. Источник данных

**Online Retail II** — UCI Machine Learning Repository, набор №502.
Реальные транзакции британского онлайн-ритейлера (подарки, товары для дома)
за период 01.12.2009 – 09.12.2011.

| Характеристика | Значение |
|---|---|
| Формат | Excel `.xlsx`, 2 листа (`Year 2009-2010`, `Year 2010-2011`) |
| Объём | ~1 067 371 строка |
| Гранулярность | строка товарной позиции в счёте-фактуре (invoice line) |
| Ссылка | https://archive.ics.uci.edu/dataset/502/online+retail+ii |

Поля источника:

| Поле | Описание |
|---|---|
| `Invoice` | номер счёта; префикс `C` — возврат (credit note) |
| `StockCode` | артикул товара |
| `Description` | наименование товара |
| `Quantity` | количество (отрицательное — возврат/корректировка) |
| `InvoiceDate` | дата и время операции |
| `Price` | цена за единицу, GBP |
| `Customer ID` | идентификатор клиента (может отсутствовать) |
| `Country` | страна клиента |

### 3.1. Staging (`stg_online_retail`)

Сырые данные 1:1 из файла, все содержательные поля — строкового типа, плюс
технические колонки:

- `_source_sheet` — из какого листа Excel пришла строка;
- `_loaded_at` — момент загрузки;
- `_row_hash` — SHA-1 от нормализованной строки для дедупликации и
  идемпотентной перезагрузки.

Назначение: точка «приземления» данных без потерь, изоляция преобразований от
источника, возможность переиграть трансформацию без повторного чтения Excel.

### 3.2. Хранилище — схема «звезда»

**Измерения (dimensions):**

| Таблица | Ключ | Содержание |
|---|---|---|
| `dim_date` | `date_key` (YYYYMMDD) | календарь: год, квартал, месяц, номер недели ISO, день недели, признак выходного, название месяца |
| `dim_customer` | `customer_key` | `customer_id`, страна, дата первой и последней покупки, число заказов, признак «гость» (заказ без ID) |
| `dim_product` | `product_key` | `stock_code`, эталонное описание, укрупнённая категория (эвристика по описанию), признак служебного кода (POST, MANUAL, BANK CHARGES …) |
| `dim_country` | `country_key` | нормализованное название страны, регион |

**Факт (`fact_sales`)** — гранулярность = товарная позиция в счёте:

| Поле | Тип | Смысл |
|---|---|---|
| `sales_key` | BIGINT PK | суррогатный ключ |
| `date_key` | FK → `dim_date` | дата операции |
| `customer_key` | FK → `dim_customer` | клиент |
| `product_key` | FK → `dim_product` | товар |
| `country_key` | FK → `dim_country` | страна |
| `invoice_no` | VARCHAR | номер счёта (для подсчёта числа заказов) |
| `quantity` | INT | количество |
| `unit_price` | DECIMAL(10,2) | цена за единицу, GBP |
| `gross_amount` | DECIMAL(12,2) | `quantity * unit_price` |
| `is_return` | TINYINT | 1, если счёт — возврат (`Invoice` начинается с `C`) |

### 3.3. Витрины (VIEW)

Инкапсулируют типовые агрегаты, используются и в SQL-отчёте, и в Python, и в дашборде:

| Витрина | Что показывает |
|---|---|
| `v_revenue_monthly` | выручка, число заказов, средний чек по месяцам |
| `v_top_products` | топ товаров по выручке и количеству |
| `v_sales_by_country` | продажи и клиенты в разрезе стран |
| `v_customer_rfm` | Recency / Frequency / Monetary по каждому клиенту |
| `v_cohort_retention` | удержание клиентов по когортам месяца первой покупки |
| `v_returns_monthly` | сумма и доля возвратов по месяцам |

## 4. Компоненты и поток управления

| Каталог | Скрипт | Роль |
|---|---|---|
| `core/` | `config.py`, `db.py`, `logs.py` | общий конфиг (`.env`), фабрика подключений SQLAlchemy, логирование |
| `etl/` | `01_extract.py` | скачать (если нет) и прочитать Excel → `data/processed/raw_sales.parquet` + профиль качества данных |
| `etl/` | `02_transform.py` | очистка, типизация, дедуп, обогащение → parquet-таблицы `dim_*`, `fact_sales` |
| `etl/` | `03_load.py` | создать схему (DDL), залить staging и звезду, создать витрины |
| `etl/` | `run_pipeline.py` | оркестратор: последовательный запуск 01 → 02 → 03 |
| `database/` | `01_create_database.sql` | `CREATE DATABASE` + пользователь приложения (запуск под `sudo mysql`) |
| `database/` | `02_create_schema.sql` | DDL: staging + `dim_*` + `fact_sales` + индексы |
| `database/` | `03_load_data.sql` | наполнение `dim_date`; `INSERT … SELECT` из staging в звезду (SQL-вариант трансформации) |
| `database/` | `04_analytics_queries.sql` | определения витрин + набор аналитических `SELECT` для отчёта |
| `analytics/` | `01_kpi_analysis.py` | сводные KPI: выручка, AOV, клиенты, доля возвратов, рост MoM |
| `analytics/` | `02_sales_analysis.py` | тренды, сезонность, ABC-анализ, топы, разрез по странам, RFM + KMeans |
| `analytics/` | `03_visualization.py` | графики Plotly → `reports/figures/`, сборка `reports/report.html` (Jinja2) |
| `dashboard/` | `app.py` | интерактивный дашборд Streamlit поверх витрин DWH |

Идемпотентность: повторный прогон конвейера пересоздаёт parquet-снимки и
перезаливает таблицы (`TRUNCATE` + `INSERT`), результат детерминирован.
